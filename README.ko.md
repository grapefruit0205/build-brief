# Build Brief

[English](README.md) | 한국어

Build Brief는 일상적인 소프트웨어 요구를 실제 상황에 맞는 엔지니어링 지시문으로 컴파일하고, 작업에 비례하는 Design Contract가 기록될 때까지 지원되는 로컬 수정 도구를 막는 작은 Codex 플러그인입니다.

이 플러그인은 **아키텍처 패턴 선택기**가 아닙니다. 사용자에게 모듈러 모노리스, 마이크로서비스, 이벤트 드리븐, 배치 처리, 함수형 같은 용어 중 하나를 고르게 하지 않습니다. 요구사항과 실제 코드베이스를 읽고, 그 상황에 필요한 설계 의미만 동적으로 구성한 뒤 각각을 구체적인 구현 또는 검증 결과로 번역합니다.

## LLM이 이미 설계할 수 있는데 왜 사용하나요?

성능이 좋은 코딩 모델은 자연어만으로도 설계를 추론할 수 있습니다. Build Brief가 모델에 새로운 지능을 추가하는 것은 아닙니다. 대신 모호한 요구사항, 여러 개발자나 에이전트 사이의 전달, 놓치기 쉬운 불변 조건이 있는 작업에서 그 추론을 더 반복 가능하고 명시적이며 전달하기 좋은 형태로 만듭니다.

기본 인터페이스는 자연어입니다. 설계 판단을 확인하고 싶거나, 암묵적인 제약을 일관되게 다루고 싶거나, 다시 사용할 수 있는 구현 지시문이 필요할 때 Build Brief를 사용하세요.

## 동작 방식

```text
자연어 요구
  → 비단순 작업에만 자동 활성화
  → 가장 좁은 관련 저장소 맥락 확인
  → 작업에 비례하는 Design Contract 완성
  → 저장소 외부에 Mutation Gate 통과 기록
  → 요청에 따라 구현·검토·비교 또는 전달
```

상황에 따라 상태 전이, 도메인 불변 조건, 계약, 동시성, 일관성, 실패 처리, 데이터 수명주기, 호환성, 보안, 관측성, 배포 전환, 완료 증거 같은 의미를 도출할 수 있습니다. 이는 닫힌 체크리스트가 아니라 열린 설계 언어입니다.

## 하이브리드 호출, 아키텍처 우선 실행

Build Brief는 호출 방식을 혼합합니다.

- **자동 발견:** 구현 의미가 암묵적으로 포함된 비단순 요청에는 사용자가 플러그인 이름을 몰라도 Skill이 활성화될 수 있습니다.
- **명시적 호출:** 설계 검토나 재사용 가능한 지시문이 필요할 때 `$build-brief`로 활성화를 보장합니다.
- **제외 경로:** 용어 설명에는 활성화하지 않습니다. 단순하고 완전히 지정된 수정은 전체 설계 경로를 생략하지만, 실제 수정 전에는 항목별 한 줄짜리 compact contract를 사용합니다.
- **수정 안전망:** 지원되는 로컬 쓰기 도구가 실행되기 전, 소유 경계·불변 조건·구현 단위·완료 증거가 들어간 최소 계약을 요구합니다.

중요한 구현 작업에서는 코드, 테스트, 설정 또는 스키마를 변경하기 전에 구현 가능한 Design Contract를 완성합니다. 계약은 현재 시스템 경계와 관찰 가능한 동작에서 시작해 불변 조건, 책임, 상태, 계약, 실행 흐름, 중요한 실패 의미, 구현 단위와 완료 증거 순서로 내려갑니다. 가벼운 라이프사이클 Hook은 자동 Skill 발견이 누락되어도 지원되는 로컬 수정 도구에 같은 순서를 적용하며, 단순 수정은 항목별 한 줄짜리 compact contract로 통과합니다.

이 게이트는 작업에 비례합니다. 요청한 변경에 중요한 설계를 고정할 뿐, 전체 시스템 아키텍처를 미리 얼려버리지 않습니다. 게이트 전에도 읽기 전용 탐색은 가능하며, 저장소 전체가 아니라 요청된 동작의 진입점부터 확인합니다.

반복되는 컨텍스트 비용을 제한하기 위해 Hook은 모든 요청을 분석하거나 다시 쓰지 않고, 세션 시작 때 짧은 정책을 한 번만 추가합니다. 로컬 런타임은 아키텍처를 분석하지 않고 네트워크도 호출하지 않으며, 지원되는 읽기 전용 호출·게이트 명령·수정 호출만 구분합니다. 자동 Skill 발견이 누락되면 첫 번째 지원 대상 수정 시도를 거부하고 복구 방법을 알려주므로, 에이전트가 계약을 통과시킨 뒤 다시 시도할 수 있습니다. 보조 reference 파일도 범위가 넓거나 동작이 명확하지 않은 변경에만 읽습니다.

## 예시

입력:

> 재고가 5개 아래로 내려가면 구매 담당자에게 한 번만 알려줘. 짧은 시간에 재고 변경이 여러 번 들어올 수도 있어.

플러그인은 단순히 “이벤트 드리븐과 멱등성을 사용하세요”라고 답해서는 안 됩니다. 모든 저재고 저장이 아니라 임계값 통과를 감지하고, 동시 변경에서도 중복 억제가 안전하도록 만들며, 알림 실패 동작을 정하고, 경계값과 경쟁 상태를 검증하라는 실행 결과로 번역해야 합니다.

## GitHub에서 설치

플러그인 마켓플레이스를 지원하는 Codex 버전과 `python3`(Windows에서는 `py -3`)로 실행할 수 있는 Python 3.10 이상이 필요합니다.

```bash
codex plugin marketplace add grapefruit0205/build-brief
codex plugin add build-brief@build-brief
```

설치 후 ChatGPT 데스크톱 앱을 다시 시작하고, 안내가 나타나면 포함된 Build Brief Hook을 검토·신뢰하세요. Codex CLI에서는 `/hooks`로 확인할 수 있습니다. Hook 정의가 바뀌면 다시 검토해야 합니다. 그다음 새 대화를 시작하세요.

## 사용법

평소에는 자연어를 사용하고, 특정 모드를 보장하고 싶을 때 명시적으로 호출합니다.

내부 설계 게이트 통과 후 자동 구현:

```text
$build-brief 기존 전체 환불 동작을 바꾸지 않으면서 레거시 결제 코드에 부분 환불을 추가해줘.
```

코딩 전 검토:

```text
$build-brief 설계 계약을 먼저 보여주고 승인받기 전에는 코딩하지 마.
```

지시문만 작성:

```text
$build-brief 다른 개발자에게 넘길 구현 지시문만 작성하고 코딩은 하지 마.
```

## 설계 원칙

- 사용자의 제품 의미, 범위, 권한을 보존합니다.
- 기존 저장소가 있다면 번역하기 전에 실제 코드를 확인합니다.
- 고정된 패턴 목록에서 고르지 않고 상황으로부터 설계 언어를 생성합니다.
- 모든 설계 용어를 구체적인 구현 또는 검증 결과에 연결합니다.
- 작업에 비례하는 Design Contract가 설계 게이트를 통과하기 전에는 구현 파일을 변경하지 않습니다.
- 가장 좁은 관련 증거부터 확인하고 중요한 미확정 동작이 있을 때만 탐색 범위를 넓힙니다.
- 구현을 요청받았다면 설계 문서에서 멈추지 않고 지시문을 실행합니다.
- 작은 변경은 작게 유지하고 설계 용어를 장식처럼 사용하지 않습니다.

## 저장소 구조

```text
.codex-plugin/plugin.json             플러그인 매니페스트
.agents/plugins/marketplace.json      GitHub 마켓플레이스 항목
skills/build-brief/SKILL.md           Skill 진입점
skills/build-brief/references/        조건부 번역 가이드
hooks/hooks.json                      Codex 라이프사이클 Hook 설정
hooks/build_brief_gate.py             로컬 요청별 수정 안전망
evals/golden-prompts.yaml             활성화 및 의미 검증 사례
tests/test_build_brief_gate.py        결정적인 Hook 동작 테스트
```

이번 릴리스에는 MCP 서버, 앱 연결, 외부 API 호출 또는 자격 증명 요구사항이 없습니다. Hook 상태는 작업 저장소가 아닌 Codex 제공 `PLUGIN_DATA`에 저장됩니다. 계약 원문 대신 digest만 보관하고 오래된 상태는 정리합니다.

## 검증

`evals/golden-prompts.yaml`에는 활성화되어야 하는 사례, 활성화되면 안 되는 사례, 경계 사례와 한국어 사례가 들어 있습니다. 이 파일은 기대 동작과 의미 불변 조건을 정의하며, 측정된 벤치마크 결과를 주장하지 않습니다.

구조 검증:

```bash
python3 /path/to/skill-creator/scripts/quick_validate.py skills/build-brief
python3 /path/to/plugin-creator/scripts/validate_plugin.py .
python3 -m unittest discover -s tests -v
```

행동 검증에서는 같은 대표 요청을 플러그인 없음, Skill만 사용, Skill과 Hook 사용 조건으로 실행합니다. 자동 활성화, 게이트 전 수정, 작업 정확성, 빠진 불변 조건, 불필요한 아키텍처, 추가 질문, 첫 수정까지의 시간, 토큰, 반복 정책 컨텍스트 증가량, 게이트 재시도, 도구별 Hook 지연과 완료 증거를 비교합니다.

## 현재 범위

자동 Skill 발견은 여전히 모델의 판단을 거치므로 과잉 활성화되거나 누락될 수 있습니다. 결정적인 Mutation Gate가 첫 번째 지원 대상 쓰기 시점에서 누락을 잡아내지만 Skill 선택 자체를 결정적으로 만들지는 않습니다.

Mutation Gate는 구조적으로 유효한 계약이 기록될 때까지 `apply_patch`와 보호 대상 Bash 명령 같은 지원되는 로컬 도구 경로를 차단합니다. 다만 완전한 보안 경계는 아닙니다. 사용자가 Hook을 신뢰하고 활성화해야 하며 일부 특수 도구 경로는 Codex 라이프사이클 Hook을 통과하지 않을 수 있습니다. Hook은 계약의 구조만 확인하고, 의미적 완성도는 Skill·저장소 증거·행동 평가가 담당합니다. 반복되는 프롬프트 컨텍스트는 피하지만 지원 대상 로컬 도구를 호출할 때마다 표준 라이브러리만 사용하는 작은 Python 프로세스를 시작하므로, 명령 호출이 아주 많은 작업에는 도구별 지연이 조금 남습니다.
