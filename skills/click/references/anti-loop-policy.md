# Anti-loop Policy

Apply the build guards after the id bound to the staged Click contract has been approved and passed. In Always ON code-review mode, apply only the read-only observation guards without requiring a build contract. Manual work where Click was not explicitly invoked remains fail-open.

## Observable guards and advisory guidance

1. **Reuse successful evidence.** Approved read-only argv requests are executed with `shell=False` by the local observation runner. Compatible simple Bash reads are converted to the same request. Before a tracked read executes, the runner atomically claims its active revision, digest, one-use token, replay state, and freshness. Only an unclaimed startup reservation expires after 30 seconds; once claimed, the read remains active until its synchronous result is recorded or the user explicitly cancels. The runner stores a normalized request digest, mutation revision, exit code, output size, and status—not argv or output. An identical successful read or search is blocked until an in-scope mutation clears the evidence ledger.
2. **Retry bounded failures, not loops.** A failed command or output larger than 48,000 bytes may be retried unchanged once. If it still fails or remains incomplete, narrow or change the command. Do not repeat it again.
3. **Keep planning non-authoritative (advisory).** `update_plan` and equivalent host plan tools remain available in armed, staged, approved/passed, and review turns. A plan update cannot stage, approve, replace, or widen the active contract; it cannot change the contract digest, mutation authority, or evidence state. Avoid unnecessary parallel planning and implement directly from the compact contract when practical. Same-turn second staging, same-turn pass, and mid-run contract replacement remain hard lifecycle denials. If the approved outcome or boundary must change, stop and ask the user.
4. **Prefer narrow follow-up after broad context (advisory).** In approved implementation and review, a broad repository inventory may establish context. A later distinct-digest broad request remains available with non-blocking narrowing guidance even while another broad inventory is running or after one succeeds. An exact-digest request that is already running or successful remains blocked by the separate observation reuse and replay rule. Path-scoped inventory and concrete content searches remain available, and a failed exact request follows the normal bounded retry rule. Inventory count and advisory output cannot change contract, mutation, or evidence authority.
5. **Make write intent explicit.** An ambiguous implementation command must use `click-gate mutate`; ordinary edit tools remain deterministic mutations. Direct active Bash is not guessed writable.
6. **Keep verification in one cumulative budget.** Final checks use protocol-v2 `click-gate verify` entries that bind every check to a declared argv source through `evidence_id` and submit `targeted`, `broad`, or `deep` classes. A request may cover any nonempty subset of unresolved argv sources. The first accepted check group for each source reserves its exact digest and Hook-inferred units for the active contract; cumulative reservations must fit the approved scale, so separate requests cannot split around the ceiling.
7. **Do not mutate through verification.** Python `-c` and direct Python scripts are rejected as checks. In Git worktrees, a final batch that changes tracked or pre-existing non-ignored untracked content fails stale. New non-ignored paths are reported, and obvious new source, application, library, configuration, or migration paths also fail stale; ignored paths remain outside this snapshot.
8. **Deduplicate Browser evidence by input.** The canonical Browser MCP tool is denied during an approved contract unless `verification.evidence` contains one referenced source with `kind: "browser"`. Calls remain serial. A normalized input that succeeds is blocked on repetition for the current revision; a failed input gets one identical retry and is then blocked, while a different input remains available. Tool timeouts over 30 seconds, explicit waits over five seconds, unassigned shadow sessions, and replay after explicit evidence finalization are blocked. There is no normal three-call or 90-second cap; a 256-unique-input ceiling protects state size. Once observed, a later distinct failure does not demote the source. A later mutation resets the Browser ledger.
9. **Own server lifecycles.** Recognizable long-running development servers are rejected by `mutate` and must use `click-gate service` start/stop. A Click-owned supervisor retains the exact isolated child, responds to explicit stop and `SessionEnd`, and enforces a two-hour lifetime ceiling.

## Evidence economy

For each approved `done_when` condition, reference exactly one cheapest sufficient source from the structured `evidence` registry through `primary_evidence`. One source id may cover several conditions. Do not duplicate an automated result with browser, manual, hosted, or external proof of the same condition, and do not exhaustively enumerate equivalent interactions or timed progression when one deterministic or representative scenario is sufficient. Collect each source once after the last relevant mutation, explicitly finalize non-argv sources, reuse current successful evidence, and stop collecting when every declared source is current. An exact successful argv check is skipped only when the same active contract and mutation revision, normalized check group, protected Git tree, canonical execution environment, and executable fingerprint still match. A new mutation revision never auto-promotes stale evidence; non-Git or incomplete receipts rerun. Before declaring the contract complete, stop any managed service. A contract with no argv source does not need a ceremonial local batch.

The Skill and semantic grader still decide whether a source is sufficient and whether two different sources duplicate the same semantic condition. The Hook independently runs bound argv checks, meters the canonical Browser MCP path, and records per-id completion. Hosted, manual, and existing completion are explicit attestations; unmatched connectors remain outside the independently observed boundary. Do not exploit an unmatched path to create a shadow verification suite.

## Read-only code review

When Always ON is active and the user requests code review without changes, run `click-gate review`. Do not create or approve a build contract. Use structured inspection or compatible simple direct reads. Prefer focused follow-up after broad repository context. A distinct-digest broad request remains available with non-blocking narrowing guidance even while another broad inventory is running or after one succeeds; an exact-digest running or successful observation remains blocked for the review turn. Mutations remain rejected while review mode is active. Plan and inventory guidance is non-authoritative and cannot turn review state into mutation authority.

Questions, explanations, and simple read-only lookups do not enter review mode and are not recorded in the observation ledger.

A source mutation clears the successful observation ledger and makes completion evidence stale because earlier results may describe different code. Git-ignored content, external dependencies, and external system state are outside the protected tree receipt. A read/search or final verification already running blocks a concurrent mutation so the recorded result cannot silently describe different code.

## What the Hook cannot observe

The Hook cannot inspect hidden reasoning, detect a plan written only in prose, cover reads performed through an unmatched connector or hosted tool, prove that a natural-language boundary was obeyed semantically, or stop a custom wrapper from concealing work. These guards reduce visible tool loops; they are not a reasoning-token cap, semantic proof, or security/resource sandbox.

When a guard blocks an action, use existing evidence, narrow the command, make the necessary in-scope correction, or report a real boundary blocker. Do not rename or wrap the same work merely to bypass the guard.
